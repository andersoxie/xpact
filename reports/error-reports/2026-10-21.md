## Error 1: loop variant in `normalized_input` fails on every input with a CR

| Item | Value |
|---|---|
| Command | `xpact_benchmarks.exe --conformance-file cr-lf.xml` (`FinalizedAssertions`) |
| Input | `cr-lf.xml`: `3C 72 3E 0D 0A 3C 2F 72 3E`, SHA-256 `5b7e3147…2a9fed` |
| Exit status | 1 |

**Expected:** `XPACT_CONFORMANCE	ACCEPT`, exit 0.
**Actual:** `XP_PARSER normalized_input @8  a_input.count - i + 1: Non-decreasing loop variant or negative value reached.`

### Observations (confirmed)

- The same input without the CR (`lf.xml`) is accepted with assertions on. Both are accepted with assertions off.
- `src/xp_parser.e:4468-4469`: on `'%R'` the loop sets `l_needs_copy := True` but does not change `i`; the variant `a_input.count - i + 1` (line 4477) does not decrease.
- 1,357 W3C cases crash here, all of them files with a CR.

### Possible explanations (not confirmed)

The loop ends correctly through `l_needs_copy`, so the code is right and the variant is wrong (like B03, #3). See #28.
