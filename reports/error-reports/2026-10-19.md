  was neither `Xml_finished` nor `Xml_suspended`.
- With `suspend_gc_during_parse = True`, `parse` runs the work through
  `XP_GC_CRITICAL_SECTION.execute (agent parse_status_into_cell ...)`
  (`xp_native_parser.e:745-749`).

  On/Workbench, On/Finalized. Only the end of the console output was saved, so
  the results of the two assertions-off cells are not in this report.
  On/Finalized never ran, because the script stopped.
- The assertions-off cells can't be counted as passes even if they showed exit
  code 0. The failure signal there is a `check`, which is compiled out
  (`TODO_CODE_REVIEW.md:84-85`, known bug).

### Possible explanations (not confirmed)

- `parsing_status` may be set inside the agent/critical section on a path that
  does not update it (or updates a copy). Then `Result` would be fine, but

  checked.

## Error 3: "The input line is too long" while importing the MSVC environment

| Item | Value |
|---|---|
| Command | `.\scripts\run_eiffel_test_matrix.ps1` (no parameters, so `-AssertionMode All -BuildMode All`) |
| Failed step | Before any compilation, while dot-sourcing `scripts\import_msvc_environment.ps1`, which runs `cmd.exe /s /c "vcvars64.bat >nul && set"` (line 22) |
| Assertions / mode | None ran. The script stopped before the first cell. |
| Loaded library | None |
| Callbacks / chunks / input | n/a |
| Exit status | Nonzero (the script stopped at a `throw`) |

**Expected:** the MSVC environment loads, then the four matrix cells run.

**Actual:** `cmd.exe` refused the command line, so `vcvars64.bat` failed.

```text
The input line is too long.
The syntax of the command is incorrect.
Failed to import Visual Studio C++ environment from C:\Program Files\Microsoft Visual
Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat
At ...\scripts\import_msvc_environment.ps1:24 char:2
+     throw "Failed to import Visual Studio C++ environment from $VcVar ...
```

### Observations (confirmed)

- "The input line is too long." is a `cmd.exe` message. It appears when an
  expanded command line or environment variable is longer than cmd's limit of
  about 8,191 characters.
- This run came after the `run_phase1.ps1` run (error 2) and the
  `build_native_eiffel.ps1` run (error 1). Both import the MSVC environment into
  the process with `Set-Item Env:...`.
- In a fresh shell, PATH is about 1,040 characters (user PATH 511, machine
  PATH 526), well under the limit.

### Possible explanations (not confirmed)

- Each import in the same PowerShell window prepends the Visual Studio folders
  to PATH again (and to `INCLUDE`, `LIB` and `LIBPATH`). After a few runs, PATH
  goes over cmd's limit and `vcvars64.bat` itself fails.
  To check: run `$env:Path.Length` in the window where it failed, then run the
  same command again in a brand-new PowerShell window.
- If this is confirmed, the script should skip the import when the environment
  is already loaded (for example when `$env:VCToolsInstallDir` is set), or each
  script should run in a new process.
