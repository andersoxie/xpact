For your XPact website, I would take security seriously from the beginning, especially because users will be uploading XML files to your server, which then processes those files using your native xpact.dll.

My recommendation is to use multiple layers of security, rather than relying on one security company.

There is an important distinction:

Website security: Protects your website and server against attacks, bots, malicious requests and DDoS.

File upload security: Checks uploaded files for malware, malicious content, oversized files and potentially dangerous structures.

Application security: Finds vulnerabilities in your own code, APIs, dependencies and configuration.

A firewall alone cannot protect you against every malicious XML file.

What I would actually implement for XPact
Your project has a particular security challenge:

A user uploads an XML document → your backend receives it → the backend sends it to your native Eiffel/C DLL → the parser processes the document → results are returned.

The dangerous part isn't necessarily the upload itself. It's what the uploaded document can make your parser or server do.

For example, someone could upload an XML document designed to:

Consume all available memory.

Cause extremely deep or recursive parsing.

Trigger an XML entity expansion attack (XML bomb).

Attempt to make the server read local files.

Make the parser access external websites or internal network addresses.

Exploit a vulnerability in the native DLL.

OWASP specifically identifies these risks.

For XML specifically, I would pay particular attention to:

Disable DTDs if they aren't required.

Disable external entity resolution.

Prevent external network access from the parser.

Limit XML document depth and entity expansion.

Set processing timeouts.

Limit memory consumption.

What about AWS?
There is another major provider worth considering: Amazon Web Services (AWS).

Its Amazon GuardDuty includes Malware Protection for Amazon S3, which automatically scans newly uploaded objects. However, this is particularly useful if you store uploads in Amazon S3 rather than directly on your Windows server.

My final recommendation
My preferred combination
For your current XPact project, I would choose:

Cloudflare – Protect the public-facing website.

OPSWAT MetaDefender – Add file scanning if the threat model and cost justify it.

Your own application-level security – Secure the XML parser and isolate the worker. This is non-negotiable.

I would not pay for an expensive enterprise security package immediately. Start with Cloudflare, implement the OWASP recommendations, and investigate OPSWAT when you're ready for production.

One more important point: Antivirus scanning does not establish that an XML document is safe. A perfectly malware-free XML file can still cause a parser vulnerability or resource-exhaustion attack.

For XPact, parser hardening and worker isolation are arguably more important than antivirus scanning.

My suggested next step would be to create a proper XPact Security Architecture & Threat Model covering the API, uploads, Windows worker, native DLL, XML parser and server configuration, so you can implement and test each security layer before making the website public.
