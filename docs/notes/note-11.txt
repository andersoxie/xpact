WHAT THE CRASH IS
- Access violation in the Eiffel GC, hybrid_mark, instruction movzx ebp, word ptr [rdi-0Ch]
  (reading the header of the object to mark). Stack: special_malloc -> partial_scavenging ->
  run_collector -> hybrid_mark (6 deep), called from {HASH_TABLE}.make <- accommodate <- put
  <- {XP_PARSER}.put_general_entity <- parse_entity_declaration <- process_dtd_subset ...
- The reference in rdi is a heap pointer with byte 6 = 0x01 (e.g. 0x0001_012d_2a38_c9e8).
- Minidumps: in EVERY crash the bad 0x01 byte sits at an address ending in ...38c9be.
  Only the low 24 bits match; the heap range and the offset in it differ. What lives there
  differs too (an "entity-decl:..." event string's area, a 6-char string, a reference array).
  => something writes 0x01 to a computed address. Not a field of one particular object.

RULED OUT
- Deep recursion (aliases are followed in a loop), aliasing of scanner input, threads/timers,
  clock or randomness in src/ or native/, memory pressure (69 MB peak), machine load alone
  (the paired run: same load, only some builds fail), Eiffel out-of-bounds writes (the
  assertions tier crashes without any precondition violation first).

HOW TO REPRODUCE / TOOLS (all in reports/mass-xpact-issue-0020/logs/tools/probe/ on perf/static-string-input)
- probe.c: linked into a copy of the libexpat runner. A vectored exception handler installed
  before main writes av-<pid>-<n>.txt (registers + RtlVirtualUnwind stack) and a minidump to
  %XPACT_CRASH_DIR% on the first 3 access violations. No debugger attached, so the timing is
  unchanged (minidbg.c, a real debugger, never saw the crash in 7 runs).
- build.ps1: relinks the runner from build\libexpat-native-static\cbuild\...\Debug\*.obj + probe.obj.
  selftest.c: a program that faults on purpose, to check the probe writes its files.
- stress-probe.ps1 <dll dir> <runs> <tag>: runs the test with that DLL first on PATH; saves the
  full output of every non-passing run.
- run4.sh / prev16.sh / asrt.sh: 4 loops in parallel (the parallel load raises the crash rate).
- Mapping: relink the DLL with -MAP (dbg-build.ps1), then RVA -> map symbol -> F_code comment
  (/* {CLASS}.feature */). SAVE the F_code name table before the next ec run overwrites it.
- dumpmem.py <dump> <hex addr> [bytes]: memory from the minidump; region.py: the range holding it.
- dumpbin /disasm /range:... (dis.ps1) for the faulting instruction.
