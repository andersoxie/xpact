THE BUG
- test_accounting_precision, doc 10 "<e>&amp;&apos;&gt;&lt;&quot;</e>" byte by byte:
  indirect bytes 60 instead of 5. Predefined refs add to expanded_entity_bytes; the resume
  path re-parses the pending text run each call -> counted again. Callbacks were correct, so
  traces/CRC/C# tests could not see it.
- Fix: resume_entity_bytes saved at each checkpoint (token start / after last general ref /
  end), restored in continue_prefix.
- LESSON: any parser-state counter that a re-parsed text run touches must be part of the
  checkpoint. Others to keep in mind if the resumable set ever grows: amplification/direct
  counts, position counters (already handled), namespace/attribute state.
- LESSON: run the Expat C suite early - it checks internal counters my tools do not.
