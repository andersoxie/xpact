ROOT CAUSE OF SLOWNESS (confirmed in code)
- xp_native_parser.e parse_with_current_gc_policy: every XML_Parse appends to input_buffer,
  then decoded_input(whole buffer) -> parser.parse_prefix(whole) which starts with reset and
  re-parses from byte 1; already delivered callbacks are suppressed by count
  (handler.prepare_callback_replay (delivered_callback_count)).
- Text split across calls = ONE callback index whose delivered length grows
  (delivered_character_data_lengths), so replay delivers only the new suffix.
- Also O(n) per call: normalized_input (whole), context_source_buffer twin,
  incomplete_markup_prefix_start scans from 1.

DESIGN CHOSEN FOR #1
- Fast path "resume": keep the parser state (no reset), keep one growing normalized buffer
  (positions stay absolute = identical numbers), continue the token loop from a checkpoint.
- Checkpoint = start of the last incomplete markup, or start of the last text run that reached
  the end of input (that text run is re-parsed; suppression trims the delivered prefix).
- Keep callback numbering identical to the legacy replay so the legacy path can be used as a
  fallback at ANY call (input_buffer is kept whole for that reason).
- Fallback to legacy for: errors, suspension, external entity parsers, non-identity encodings,
  diagnostic events, reparse deferral, direct start-tag emission, general entity refs in the
  pending text run.
