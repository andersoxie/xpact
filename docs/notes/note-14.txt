NOTE 14 - 2026-11-05 - long text runs in pieces were quadratic (#51), and the "profile without handlers" trap

SHORT
- A document with ONE long text run, fed in small pieces, was quadratic: a 100 KB run took
  7.4 s byte by byte. pr-xml-utf-8.xml hid it (its text runs are short).
- Cause: on every call the continued text run (#11) moved the position back to the run start and
  counted lines/columns forward over the whole run again (note_position -> advance_position_to).
- Fix #51 (PR #52): a high-water mark in advance_position_to and a one-entry memory of the last
  retreat target in retreat_position_to, both with line and column, cleared on recompute/reset.
  100 KB run 7,394 -> 102 ms; 4,000-line text 5,446 -> 100 ms; pr-xml-utf-8 184 -> 145 ms.
  All positions identical (3 new 4,000-line documents + W3C trace + DLL tests + Test 2).
