v4 (fix after the trace diff, events-7/default-7/suspend-*):
- The old path cuts an unfinished UTF-8 character off non-final input BEFORE deciding reparse
  deferral (complete_encoded_prefix_count in decoded_input). The resume path decided on the
  whole buffer, so callbacks were delivered one call earlier in 4 W3C files (Japanese UTF-8,
  XML 1.1 chars). Fix: should_defer_reparse_callbacks_on_prefix (keep_head + put the <= 3 tail
  bytes back) and parse only up to that count; XML_GetInputContext gets context_source_count.
- LESSON: a postcondition like "same_string (old input_buffer.twin)" copies the whole buffer on
  every call in assertion builds = quadratic again. Use count checks.

v5 (fix found by thinking about uncovered paths, then CONFIRMED with a new trace mode "abort"):
- XML_StopParser(p, XML_FALSE) inside a callback during a resumed parse: the resumed parse set
  the error, then the code fell back to the full replay; the stop flag was still set, so the
  replay reported the abort at 1:0:0 (wrong position) in 1,238 traced documents.
- Fix: an error in a resumed parse is accepted (parser state = that of a full parse). Fallback
  only when continue_prefix returns False WITHOUT error (invalid character in new bytes).
