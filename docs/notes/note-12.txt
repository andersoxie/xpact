LESSON: COMPARE AT EQUAL LOAD
- The crash rate depends strongly on machine load: ~0 in 24 with 4 runs in parallel, ~1 in 8
  with 12. A comparison between builds is only fair when they run AT THE SAME TIME
  (tools/probe/paired4.sh: 3 loops x 4 runs per build, all builds together).

WHAT THE WATCHPOINT FOUND (tools/probe/watch.c)
- Hardware write watchpoints, set in-process by a watcher thread on every heap address ending in
  38c9be (the address of the bad byte in every crash), log every write there.
- The 0x01 written there comes from {SPECIAL}.force <- {HASH_TABLE}.put <- accommodate <- force
  <- {XP_PARSER}.resolved_general_entity_name, which keeps l_seen: HASH_TABLE [BOOLEAN, STRING_8]
  while it follows the 60,000 aliases. Those writes were legitimate (the array lived there then).
- Suspected: a later True written through a stale reference to that array. The generated
  HASH_TABLE setters have the write barrier (RTAR) and every routine registers its locals
  (tools/probe/unreg-all.awk), so the stale reference is unexplained; maybe the Eiffel runtime.
- Replacing the three BOOLEAN seen-tables with HASH_TABLE [STRING_8, STRING_8]
  (branch fix/20-seen-name-tables) did NOT help: 1 crash + 1 wrong result in 12 at equal load.
