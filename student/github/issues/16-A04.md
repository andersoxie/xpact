## Goal
Verify the actual library loaded by tests, benchmarks and packaged examples. Test both workbench and finalized assertions-enabled builds and every other configuration that is still supported.

## Why
Student guide, task register A04. A comparison is only meaningful if it is known which build was measured.

## Done when
- [x] For each runner: the path and hash of the DLL actually loaded (e.g. Process Monitor, `Get-Process -Module`, or a log line)
- [x] Table: configuration -> expected library -> observed library
- [x] Mismatches filed as findings; results in `student/results/A04-loaded-library/`
- [x] Re-run the C# P/Invoke smoke test against `build\native-eiffel\xpact.dll`

## Evidence / notes
Error report, section 4.6: the bridge-only `build\native\xpact.dll` (from `build_native.ps1`) returns error 44 "Eiffel parser bridge is not installed" from a C# `XML_Parse` call. The Eiffel-backed DLL is in `build\native-eiffel\`. Make sure no consumer loads the bridge-only DLL by mistake.

## Update 2026-10-22
The C# program from [#37](https://github.com/andersoxie/xpact/issues/37) loads the DLL by full path and prints its path, size, date and SHA-256 in every summary, so for that runner the loaded library is known. That is one runner; the C smoke tests, `run_chunked_crc_harness.ps1` and the benchmarks still need checking.
