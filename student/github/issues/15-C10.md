## Goal
A bounded part of C10: differential-test malformed UTF-8 in text first, then in names and attributes if time permits. Split multibyte sequences at every byte boundary.

## Why
Student guide, task register C10. In the baseline from 2026-10-14, `<r>` C3 28 `</r>` (invalid UTF-8) was **accepted**; it should be rejected.

Seen three times so far: with `xpact.exe --parse-file bad-utf8.xml` (error report, section 6.1), in the week 2 event trace (`student/baseline/event-trace/inputs/06-bad-utf8.xml`, ACCEPT), and in the walkthrough.

## Done when
- [x] Byte-exact fixtures: bad continuation (`C3 28`), lone continuation (`80`), overlong (`C0 AF`), surrogate (`ED A0 80`), above U+10FFFF (`F4 90 80 80`), `FF` (2026-10-26, `student/results/C10-utf8/fixtures/`)
- [x] For each fixture: xpact vs Expat verdict, for the whole input and at every split position. *xpact side done 2026-10-22 ([#37](https://github.com/andersoxie/xpact/issues/37)); Expat side 2026-10-26 ([#121](https://github.com/andersoxie/xpact/issues/121))*
- [x] Results table in `student/results/C10-utf8/`. Parser repairs (C08) stay with the experienced developers.

## Update 2026-10-22
The xpact side is done for `C3 28`, `C0 AF`, `ED A0 80`, `F4 90 80 80` (not yet `80` and `FF`) in text, attribute, name, comment, PI and CDATA, whole and at every split ([#37](https://github.com/andersoxie/xpact/issues/37), [results](../../results/dll-tests-2026-10-22/README.md)). **Finding [#39](https://github.com/andersoxie/xpact/issues/39):** 2,106 of 2,148 cases are accepted; only `C3 28` in a name is rejected, and only because `(` is not a name character. Still to do: lone `80` and `FF`, and Expat's verdicts.

## Done 2026-10-26
`80` and `FF` added; Expat 2.8.1 run through the same program ([#121](https://github.com/andersoxie/xpact/issues/121), [results](../../results/C10-utf8/README.md)). **All 3,606 UTF-8 verdicts agree**: every bad sequence rejected in every place and at every split, `é` accepted. Error code 4 in both. Two differences, reported, not repaired: xpact reports the error at 1:0 ([#122](https://github.com/andersoxie/xpact/issues/122)) and gives no events before it ([#123](https://github.com/andersoxie/xpact/issues/123)).
