3. THE 5 TESTS TO DO NEXT (in this order)
-----------------------------------------

TEST 1 - Regression test for the CR crash  (new finding, small, blocks the rest)
  Input (byte-exact, 9 bytes):  3C 72 3E 0D 0A 3C 2F 72 3E   = <r> CR LF </r>
  Expected: ACCEPT, with assertions on and off.
  Actual (verified 2026-10-21):
    file           build                          result
    LF only        xpact_benchmarks (no assert.)  ACCEPT, exit 0
    LF only        xpact_benchmarks_assertions    ACCEPT, exit 0
    CR LF          xpact_benchmarks (no assert.)  ACCEPT, exit 0
    CR LF          xpact_benchmarks_assertions    CRASH, exit 1:
                   XP_PARSER normalized_input @8, a_input.count - i + 1:
                   "Non-decreasing loop variant or negative value reached."
  Cause: in XP_PARSER.normalized_input (src/xp_parser.e:4440), when the first
    loop finds a CR it sets l_needs_copy := True but does not advance i. The
    loop still ends correctly, but the loop variant did not decrease in that
    last round, so with assertions on Eiffel stops the program.
  Why first: every file with a CR crashes (1,357 of the 1,360 W3C crashes), so
    it hides every other assertion failure. Same kind of bug as B03 (#3).
  Student part: the repro, a regression test and checking the developers' fix.
